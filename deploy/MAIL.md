# Почта сайта: `no-reply@math.egor.am`

Сайт отправляет только исходящие письма, десятки в день максимум:

| Письмо | Кому | Откуда в коде |
|---|---|---|
| Новое предложение исправления | редакторам из `PROPOSAL_NOTIFY_EMAILS` | `problems/notifications.py` |
| Решение по предложению (принято / отклонено) | автору, если у него есть почта | `problems/notifications.py` |
| Восстановление пароля | пользователю по почте из профиля | `accounts/password_reset.py` |
| Приглашение учителя | на почту из приглашения, кнопка «Отправить письмом» на странице «Учителя» | `accounts/mailing.py` |

Отправитель везде — `DEFAULT_FROM_EMAIL`, по умолчанию `Математика <no-reply@math.egor.am>`
(решение 2 плана пользователей, 18.10.2026). На ответы никто не отвечает,
входящей почты у домена нет. Пока `EMAIL_HOST` не задан, сайт работает как
раньше: письма молча не отправляются, ссылки «Забыли пароль?» и кнопок
«Отправить письмом» нет. Локально при `DEBUG` письма печатаются в консоль
`runserver`.

## 1. Какой путь выбрать

Два пути: транзакционный SMTP-релей (сервис, который отправляет письма от
имени домена по SMTP или API) или почта для домена (Яндекс 360 для бизнеса —
обычный ящик `no-reply@`, из которого сайт шлёт через `smtp.yandex.ru`).
Критерии: только исходящие уведомления, десятки писем в день, сайт и VPS в
РФ, домен `math.egor.am`.

| | SMTP-релей | Яндекс 360 для бизнеса |
|---|---|---|
| Цена при десятках писем в день | бесплатно: Yandex Cloud Postbox — 2 000 писем/мес, Resend — 3 000/мес (100/день), Brevo — 300/день, SMTP2GO — 1 000/мес, Postmark — 100/мес | бесплатного тарифа нет с апреля 2023; от ~300 ₽/мес за один ящик |
| Доступность из РФ, оплата | Postbox — Яндекс, рубли, данные в РФ. Зарубежные (Resend, Brevo, SMTP2GO, Postmark, Mailgun) карты РФ не принимают: бесплатный тариф без карты возможен, но аккаунт могут закрыть по стране без предупреждения. Amazon SES — аккаунт AWS из РФ не завести | Яндекс, рубли |
| Доставляемость | DKIM/SPF настраиваются по инструкции провайдера, репутация IP — у провайдера, есть журнал отправок и жалоб | хорошая, но ящик рассчитан на людей: суточные лимиты отправки, автоматическую рассылку с ящика могут счесть спамом и заблокировать |
| Лишнее | нет | ящик, диск, календарь — не нужны |
| Настройка в Django | SMTP с логином и паролем, как и сейчас | то же |

**Рекомендация — Yandex Cloud Postbox.** Транзакционный сервис Яндекса:
первые 2 000 писем в месяц бесплатно (дальше ≈80 ₽ за тысячу), квота по
умолчанию 200 писем в сутки и 1 письмо в секунду — для наших объёмов с
запасом. SMTP `postbox.cloud.yandex.net` (587 STARTTLS или 465 SMTPS),
логин и пароль — обычный API-ключ сервисного аккаунта, никаких скриптов
для пароля. DKIM — две CNAME-записи, ключи ротируются сами. Оплата в
рублях, аккаунт российский — риска «закрыли по стране» нет.

Запасной вариант, если Postbox почему-то не подойдёт, — **Resend**: 3 000
писем в месяц (не больше 100 в день) бесплатно без карты, SMTP
`smtp.resend.com`, логин `resend`, пароль — API-ключ (465 SMTPS / 587
STARTTLS). Зарубежный сервис: может перестать работать для российского
аккаунта в любой момент. Яндекс 360 не рекомендую: платный ящик ради
одного `no-reply@` и лимиты обычной почты.

Проверено 20.10.2026 по страницам тарифов и документации провайдеров;
лимиты меняются — перед регистрацией взгляните на актуальные.

## 2. Регистрация в Postbox (делает Егор)

1. Войти в [консоль Yandex Cloud](https://console.yandex.cloud/) с Яндекс ID.
   При первом входе создаются облако и каталог (назовите каталог
   `egormath`); нужен платёжный аккаунт в статусе «Активен» или «Пробный»
   (для физлица — привязка карты; при объёме до 2 000 писем в месяц
   списаний не будет).
2. **Сервисный аккаунт.** Каталог → «Сервисные аккаунты» → «Создать»:
   имя `postbox-sender`, роль `postbox.sender`. Он должен быть в том же
   каталоге, где будет создан адрес отправителя, — иначе отправка упадёт
   с ошибкой доступа.
3. **API-ключ.** Открыть сервисный аккаунт → «Создать новый ключ» →
   «API-ключ», область действия `yc.postbox.send`. Консоль покажет
   **идентификатор** и **секретный ключ**; секрет показывается один раз —
   сразу сохранить в менеджер паролей. Это будущие `EMAIL_HOST_USER`
   (идентификатор) и `EMAIL_HOST_PASSWORD` (секрет).
4. **Адрес отправителя.** Консоль → Cloud Postbox (в том же каталоге) →
   «Создать адрес»: домен `math.egor.am`, DKIM — «Простая» (Easy DKIM),
   логирование не нужно → «Создать адрес». На странице адреса появятся
   две DKIM-записи типа CNAME — их имена и значения нужны в разделе 3.
5. После добавления DNS-записей статус адреса сам станет «Success»
   (ответы DNS кешируются, может занять до суток; если не меняется —
   кнопка «Запустить проверку» на странице адреса).

Квоты (200 писем в сутки) при необходимости увеличиваются запросом в
консоли, раздел «Квоты»; сейчас не нужно.

## 3. DNS-записи для `math.egor.am`

Добавляются у DNS-провайдера зоны `egor.am`. В колонке «Имя» — полное имя;
если панель провайдера просит имя *относительно зоны* `egor.am`, вводите
часть до `.egor.am` (например, `math` вместо `math.egor.am`, `_dmarc.math`
вместо `_dmarc.math.egor.am`).

| Имя | Тип | Значение | Зачем |
|---|---|---|---|
| `<селектор-1>._domainkey.math.egor.am` | CNAME | из блока DKIM на странице адреса в Postbox (первая запись) | подпись DKIM, обязательна: без неё адрес не подтвердится |
| `<селектор-2>._domainkey.math.egor.am` | CNAME | из блока DKIM на странице адреса (вторая запись) | то же |
| `math.egor.am` | TXT | `v=spf1 include:spf.postbox.yandexcloud.net ~all` | SPF: разрешает Postbox слать от домена. На имени должна быть **одна** запись `v=spf1`; если такая уже есть — дописать `include:spf.postbox.yandexcloud.net` перед `~all` |
| `_dmarc.math.egor.am` | TXT | `v=DMARC1; p=none; rua=mailto:<почта Егора>` | DMARC: пока только отчёты на указанный адрес. Через пару недель чистых отчётов — `p=quarantine` |
| `math.egor.am` | A | `77.232.132.139` (IP VPS) | рекомендуется: часть почтовых серверов не принимает письма с домена, у которого нет ни A, ни MX. Альтернатива, если сайт на этот домен переезжать не будет: Null MX `math.egor.am MX 0 .` («почту не принимаем») |

Имена селекторов DKIM и значения CNAME Postbox выдаёт при создании адреса,
заранее их не узнать — поэтому в таблице они без значений. Точки в конце
значений CNAME ставить так, как требует панель провайдера.

Проверить записи с Mac до того, как трогать сервер:

```bash
dig +short TXT math.egor.am
dig +short TXT _dmarc.math.egor.am
dig +short CNAME '<селектор-1>._domainkey.math.egor.am'
```

## 4. Секреты: что и куда положить

Django читает настройки почты файлами `.secrets/<ИМЯ>` (`core/settings.py`,
`read_secret`): на VPS это `/opt/egormath/data/secrets/`, в контейнере
смонтирован как `/app/.secrets` только для чтения; на Mac — `.secrets/` в
корне репозитория. Значения вводит только Егор, в чат и в git они не
попадают.

| Файл | Значение для Postbox | Обязателен |
|---|---|---|
| `EMAIL_HOST` | `postbox.cloud.yandex.net` | да — без него почта выключена |
| `EMAIL_PORT` | `587` | нет, 587 по умолчанию; `465` — тогда SSL включится сам |
| `EMAIL_HOST_USER` | идентификатор API-ключа (шаг 3 раздела 2) | да |
| `EMAIL_HOST_PASSWORD` | секрет API-ключа | да |
| `EMAIL_USE_TLS` | `1` | нет: STARTTLS включён по умолчанию для любого порта, кроме 465 |
| `EMAIL_USE_SSL` | `0` | нет: для порта 465 включается сам, оба режима сразу Django не даёт |
| `DEFAULT_FROM_EMAIL` | `Математика <no-reply@math.egor.am>` | нет, это значение по умолчанию; домен должен совпадать с подтверждённым в Postbox |
| `PROPOSAL_NOTIFY_EMAILS` | адреса редакторов через запятую | нужен для писем о новых предложениях; без него уходят только письма авторам, сброс пароля и приглашения |

На сервере от пользователя `deploy`:

```bash
cd /opt/egormath/data/secrets
printf '%s' 'postbox.cloud.yandex.net' > EMAIL_HOST
printf '%s' '<идентификатор API-ключа>' > EMAIL_HOST_USER
read -rs P && printf '%s' "$P" > EMAIL_HOST_PASSWORD && unset P   # секрет не попадёт в историю shell
printf '%s' '<почта редактора>' > PROPOSAL_NOTIFY_EMAILS
chmod 600 EMAIL_HOST_USER EMAIL_HOST_PASSWORD
cd /opt/egormath && docker compose --env-file .env -f deploy/vps/compose.yaml restart egormath-web
```

Секреты читаются при старте, поэтому после правки нужен `restart`
(следующий `deploy.sh` пересоздаст контейнер и так). Ночной бэкап
(`backup.sh`) кладёт `data/secrets` в зашифрованный архив — новые файлы
попадут туда сами.

На Mac те же файлы в `.secrets/` нужны только чтобы отправлять настоящие
письма с локальной машины; для разработки они не нужны — при `DEBUG` без
`EMAIL_HOST` письма печатаются в консоль `runserver`.

## 5. Проверка

```bash
ssh chemolymp-demo /opt/egormath/deploy/vps/manage.sh mail_check <свой адрес>
```

Команда печатает бэкенд, хост и порт, режим шифрования, логин и отправителя
(пароль — никогда), затем отправляет тестовое письмо. Ожидаемый вывод:

```
Бэкенд: django.core.mail.backends.smtp.EmailBackend
SMTP: postbox.cloud.yandex.net:587, STARTTLS, логин <идентификатор>, таймаут 10 с
Отправитель: Математика <no-reply@math.egor.am>
Адреса редакторов (PROPOSAL_NOTIFY_EMAILS): <почта редактора>
Тестовое письмо отправлено на <свой адрес>
```

Дальше смотреть:

- **Письмо пришло?** В Gmail: «Показать оригинал» — строки `SPF: PASS`,
  `DKIM: PASS` с доменом `math.egor.am`, `DMARC: PASS`. Если письмо в
  спаме с первого раза — нормально для нового домена, отметьте «Не спам».
- **Ошибка команды «Сервер почты не принял…»** — текст ответа SMTP в ней
  же. Типичные: `535` / «authentication failed» — неверный идентификатор
  или секрет, у ключа не та область действия, у сервисного аккаунта нет
  роли `postbox.sender` или он в другом каталоге; «sender … not verified»
  — у адреса в Postbox статус не «Success» или домен в
  `DEFAULT_FROM_EMAIL` не тот; таймаут — порт закрыт с сервера, проверить
  `nc -zv postbox.cloud.yandex.net 587` (и 465) на VPS и при необходимости
  спросить поддержку Timeweb.
- **Логи сайта** при письмах из интерфейса (предложения, приглашения,
  сброс пароля): `cd /opt/egormath && docker compose --env-file .env -f
  deploy/vps/compose.yaml logs --tail=200 egormath-web | grep -i письм` —
  строки «Не удалось отправить письмо «…»» с трассировкой SMTP
  (`core.mailing`) и «Failed to send password reset email» (Django). Сайт
  при сбое почты не падает: предложение и приглашение всё равно
  сохраняются, пользователю показывается ошибка или та же страница.
- **В интерфейсе:** на странице входа появилась ссылка «Забыли пароль?»,
  на странице «Учителя» у приглашений с почтой — кнопка «Отправить
  письмом»; отправки и жалобы видны в консоли Postbox на странице адреса.

## Если выбран другой провайдер

Меняются только значения секретов; DNS — по инструкции провайдера (у всех
это DKIM + SPF `include:` + DMARC, как в разделе 3).

| Провайдер | `EMAIL_HOST` | `EMAIL_PORT` | `EMAIL_HOST_USER` | `EMAIL_HOST_PASSWORD` |
|---|---|---|---|---|
| Resend | `smtp.resend.com` | `465` (SSL) или `587` | `resend` | API-ключ |
| Brevo | `smtp-relay.brevo.com` | `587` | логин аккаунта Brevo | SMTP-ключ из раздела «SMTP & API» |
| SMTP2GO | `mail.smtp2go.com` | `587` или `465` | SMTP-пользователь из консоли | его пароль |
| Яндекс 360 | `smtp.yandex.ru` | `465` | `no-reply@math.egor.am` | пароль приложения (не пароль ящика) |
