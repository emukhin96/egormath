# Перенос черновиков с локальной машины на сервер

Перенос запускается локально после деплоя кода на сервер, включая
миграции. Скрипт не выполняет деплой и не публикует задачи в каталог.
На сервере должен существовать активный учитель `egor` (или другой пользователь,
переданный через `--username`). Для доставки нужен доступ по SSH/SCP к VPS:
по умолчанию хост `chemolymp-demo` (пользователь `deploy`, группа `docker`)
и каталог `/opt/egormath`, см. [deploy/VPS.md](../deploy/VPS.md); другие
значения — `--host` и `--app-dir`.

Из корня репозитория:

```bash
./venv/bin/python tools/transfer_textbook_batch.py 20 --username egor
```

Команда выгружает **именно партию 20**, создаёт ZIP в `artifacts/transfers/`,
проверяет наличие новой версии кода и миграции на сервере, отправляет ZIP во
временный закрытый каталог `/opt/egormath/data/var/transfers/` (в контейнере
`egormath-web` он виден как `/app/var/transfers/`), проверяет SHA-256,
справочники и изображения, затем через `deploy/vps/manage.sh` восстанавливает
черновики в транзакции. В результате выводятся новый ID,
путь `/problems/imports/<ID>/`, количество задач и изображений. ID на сервере
может отличаться от локального. Сайт: https://math.emukhin.ru.

Подготовить архив до деплоя, ничего не отправляя:

```bash
./venv/bin/python tools/transfer_textbook_batch.py 20 --prepare-only
```

После деплоя передать подготовленный архив или повторить прерванный перенос:

```bash
./venv/bin/python tools/transfer_textbook_batch.py --package /полный/путь/batch-20-ДАТА.zip --username egor
```

Для повторного запуска используйте **тот же ZIP**. Его повторная загрузка
возвращает прежнюю партию, проверяет сохранность рисунков и не перезаписывает
редакторские изменения. Экспорт после изменения черновиков создаёт иной пакет
и может создать новую партию: автоматического обновления старой партии нет.
Локальный ZIP сохраняется; временный файл на сервере удаляется после попытки
загрузки. При обрыве SSH очистка может не выполниться; каталог остаётся в `/tmp`.

## Что сохраняется

- Текст LaTeX, подпункты, таблицы, предупреждения и статусы.
- Авторские и редакторские ответы и решения, маски ответов — у задачи и
  у каждого подпункта.
- Метки экзамена и класса, теги, выбранные темы и кандидаты тем. Темы и метки
  сопоставляются по кодам, а не локальным ID; отсутствующий код прерывает перенос.
- Общие блоки и порядок вопросов №1–5; неполный блок отклоняется.
- Все файлы партии, включая неиспользованные; ссылки из задач проверяются,
  содержимое каждого файла сверяется по SHA-256 до и после записи.
- Источник и диагностика партии. Владельцем становится указанный учитель.
  Проверявшие сопоставляются по имени пользователя; отсутствующий на сервере
  проверявший заменяется владельцем. Пустое поле проверявшего сохраняется.

Текст не проходит повторный OCR, парсер или нормализацию. Перед фиксацией
транзакции записанные поля повторно читаются и сравниваются с пакетом.
При ошибке записи откатываются новые строки БД и удаляются новые файлы.
Задачи, уже импортированные в каталог, этим способом не переносятся.

Перенос сам ничего не одобряет и не запускает ИИ.

## Отдельные команды Django

```bash
./venv/bin/python public_html/manage.py export_textbook_batches /tmp/batch20.zip --batch 20
./venv/bin/python public_html/manage.py import_textbook_batches /tmp/batch20.zip --username egor --check-only
./venv/bin/python public_html/manage.py import_textbook_batches /tmp/batch20.zip --username egor
```

`--batch` можно повторять. Старый выбор последних партий через `--profiles`
сохранён. Текущий формат — версия 3. Пакеты версий 1 и 2 также читаются,
но отсутствующие в них данные восстановить невозможно: в версии 2 нет
редакторских ответов, решений и маски задачи, в версии 1 — ещё и
метаданных. Сервер со старым кодом отклоняет пакет версии 3, поэтому
сначала деплой, затем перенос. Имена файлов внутри
пакета проверяются на выход за его пределы, ZIP ограничен 2 ГБ и 20 000 записей.
Выгрузки содержат данные задач и хранятся вне Git.

Черновики выгружаются в порядке создания (порядке книги): загрузка создаёт
их в том же порядке, поэтому список партии и рубрики подборок на сервере
идут как в книге, а не по строке номера (`I.10` не встаёт перед `I.2`).

## Правки уже перенесённой партии

Если партия уже на сервере, а сверку продолжали на локальной копии,
повторно переносить её не нужно — переносится только разница.

1. До правок выгрузите исходное состояние локальной копии:
   `export_textbook_batches исходная.zip --batch <локальная>`.
2. После сверки соберите пакет правок:

   ```bash
   ./venv/bin/python public_html/manage.py make_textbook_draft_patch <локальная> исходная.zip правки.json
   ```

   В пакет попадают только изменённые строки: для каждой — её исходное
   состояние целиком (все переносимые поля и статус) и новые значения
   изменённых полей: условие, ответы, решения, подпункты, маски,
   предупреждения, рисунки и темы (по кодам). Статусы и отметки сверки не
   переносятся — одобряет человек на сервере. Правки номера, пути,
   подборки, кодов экзамена и тегов пакет не переносит: команда печатает
   их списком, их нужно повторить на сервере вручную.
   Пакет привязан к партии: профиль, название и контрольная сумма набора
   номеров задач должны совпасть с исходной выгрузкой.
3. На сервере после деплоя кода с этой командой: резервная копия партии,
   затем предпросмотр и запись.

   ```bash
   manage.py export_textbook_batches /app/var/transfers/batch-N-до-правок.zip --batch N
   manage.py apply_textbook_draft_patch N правки.json           # предпросмотр
   manage.py apply_textbook_draft_patch N правки.json --apply   # запись
   ```

   Если партия на сервере называется иначе, чем локальная, добавьте
   `--allow-other-title` (профиль и набор задач всё равно сверяются).

Строка меняется, только если её статус и все переносимые поля совпадают
с исходным состоянием в пакете; иначе она пропускается и попадает в
отчёт — правки учителя на сервере после выгрузки не перезаписываются.
Поле, уже равное новому значению (повторный запуск, та же маска,
подобранная на сервере), считается применённым. Одобренная строка после
правки возвращается на проверку: одобряли другой текст. Предупреждения
о рисунках пересчитываются по файлам серверной партии. Маски проверяются
до записи, вся запись — одна транзакция, после неё значения
перечитываются и сверяются с пакетом. Текст не проходит повторную
нормализацию.

Пакет, меняющий `\divby` в текстах, применяйте после деплоя кода
с этим макросом (KaTeX и пакеты PDF), иначе знак не отрисуется.
