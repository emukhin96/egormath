# Большая модификация системы (пп. 0–25)

Работа ведётся по pipeline: каждая тема — отдельная ветка и PR, ревью, правки, merge вручную. Пункты 22–25 — только проектные документы (реализация отдельными планами).

- Убрать акцентные односторонние рамки — в [public_html/static/css/input.css](public_html/static/css/input.css) их ровно две: `.panel-priority` (`border-top: 3px solid var(--accent)`, стр. 822) и `.hero-card` (`border-left: 4px solid var(--accent)`, стр. 880). Заменить на нейтральное выделение (фон/тень). Запрет зафиксировать в правилах стилей `docs/PIPELINE.md` (раздел 2) и `AGENTS.md`.
- Плитка «Задач в базе»: в `teacher_dashboard` ([public_html/accounts/views.py](public_html/accounts/views.py)) добавить `tasks_total = Task.objects.filter(variant_of__isnull=True).count()`, вывести в `stat-grid` в [dashboard_teacher.html](public_html/templates/accounts/dashboard_teacher.html).
- Публичная ссылка всегда в новой вкладке: добавить `target="_blank" rel="noopener"` в [worksheet_detail.html:296](public_html/templates/worksheets/worksheet_detail.html).

## PR 2 — `feat/worksheet-list-actions`: список листков (п. 1)

- Новый view `worksheet_delete` (POST, только владелец) + маршрут `<pk>/delete/`; в таблице списка — значок «×» с `confirm()`.
- «Горячее» редактирование класса: новый view `worksheet_quick_update` по образцу `task_quick_update` ([problems/views.py:70](public_html/problems/views.py)); select класса прямо в ячейке таблицы с `data-autosave="change"` (механизм [autosave.js](public_html/static/js/autosave.js) уже готов).
- Темы — popup: нативный `<dialog>` с чекбоксами тем, POST в тот же quick-update. Без сторонних библиотек.

## PR 3 — `ui/builder-polish`: конструктор листка (пп. 2, 3, 4, 5, 6)

## PR 4 — `feat/builder-inline-edit`: заголовок, имя PDF, дублирование (пп. 7, 8, 9)

- П. 9: заменить `<details class="ws-title-edit">` на клик-в-текст: `h1` и подзаголовок становятся редактируемыми по клику (скрытый input, показываемый на месте текста), сохранение через существующие `worksheet_rename`/новый endpoint + autosave. Без выпадающей формы.
- П. 7: поле `pdf_basename` (CharField, blank) у `Worksheet` + миграция. Если пусто — автогенерация: translit(первая тема) + grade + «-» + translit коротких слов title (пример `alg8-kv_ur`). Использовать в `_worksheet_pdf_response` ([worksheets/views.py:415](public_html/worksheets/views.py)) вместо `{title}-{variant}`. Ручное задание — в форме свойств.
- П. 8: «Дублировать» открывает `<dialog>` с полями (title, grade_label, pdf_basename, класс), POST → `worksheet_copy` с этими значениями → редирект в новый листок.

## PR 5 — `feat/web-tex-rendering`: отображение TeX в вебе (пп. 10а, 10б, 10в)

- Расширить templatetag `web_text` ([problems/templatetags/task_extras.py](public_html/problems/templatetags/task_extras.py)) в серверный препроцессор tex→web: `tabular`→HTML-таблица (10а); `\annot{…}`→стилизованный span, `\%`→%, `\par` и `\\`→перенос строки, прочие типовые команды (10б). KaTeX продолжает рендерить формулы, препроцессор занимается только текстовым слоем.
- П. 10в: развести «класс» и шапку `\bighead`. В сайдбаре [includes/sidebar/worksheet_detail.html:5](public_html/templates/includes/sidebar/worksheet_detail.html) сейчас «Класс: {{ worksheet.grade_label }}» — заменить на числовой `worksheet.grade`; `grade_label` показывать как «Шапка листка». Переименовать label поля в формах, при импорте left-header писать только в `grade_label`.

Значения передавать в `create_worksheet` через именованные поля формы.

## PR 8 — `feat/task-inline-edit`: карточка задачи (п. 19)

- Объединить `task_detail` и `task_edit`: на странице задачи — редактирование «по клику» (текст, ответ, решение, подпункты, класс/тема/теги/звёзды) с autosave через расширенный `task_quick_update`; формсеты подпунктов — добавление/удаление без перезагрузки. Отдельная страница `task_edit` остаётся для сложных случаев (картинки, источники), но основной сценарий — на карточке.

## PR 9 — `feat/pdf-editor`: редактор PDF для учителя (пп. 20, 21)

- Новая страница `<pk>/pdf-editor/<variant>/`: слева textarea с tex (из `worksheet_to_tex`), справа `<iframe>` c PDF; кнопка «Перегенерировать» — POST tex → новый view `compile_custom_tex` (только владелец, компиляция через существующий `services.compile_latex`, ответ PDF inline). Правки эфемерны (не сохраняются в модель).
- Контекстный сайдбар: переключатели размера шрифта (10/11/12pt), шрифта (CM / Schoolbook `fouriernc` / Palatino `mathpazo`) и бумаги (A4/A5) — JS-замены в tex-коде (`documentclass[...]`, пакет шрифта) + автоперегенерация.
- Кнопки PDF у учителя (toolbar конструктора, список листков) ведут на редактор; у ученика и на публичной странице — прямой PDF без изменений.

## PR 10 — `ui/public-page`: публичная страница (пп. 14, 15)

- П. 14: [public.html](public_html/templates/worksheets/public.html) переводится на минимальную оболочку без контекстной панели даже для залогиненных (флаг в base.html или отдельный блок).
- П. 15: консистентная строка задачи: на широких экранах звёзды «на полях» слева от номера (отрицательный отступ/выделенная колонка под звёзды в grid-строке), на узких — inline между номером и текстом без переноса (`flex-wrap: nowrap`, текст `flex: 1`). Общая разметка для public/assignment/review.

## PR 11 — `docs/proposals`: проектные документы (пп. 22, 23, 25) + документация (п. 24)

- `docs/proposals/worksheet-cart.md` — «корзина»: кнопка «в новый листок» у задач, хранение черновика (сессия или модель), UX-схема.
- `docs/proposals/semi-auto-import.md` — полуавтоматический импорт: Mathpix для распознавания PDF → LLM API (ChatGPT/Gemini) для структурирования задач, генерации ответов/решений; этапы контроля, оценка стоимости, батчинг.

- `docs/images.md` (п. 24 — пишем сразу): как пользователю добавлять картинки (`\taskpic{N}`, TaskImage, сжатие, PDF-иллюстрации), как хранит и передаёт в LaTeX API система.
