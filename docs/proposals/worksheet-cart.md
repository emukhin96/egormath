# Проект: «корзина» — сборка листка из базы задач

Статус: реализовано (сентябрь 2026), уточнено после первого ручного
прогона. Пункт 22 плана большой модификации.

## Идея

У каждой задачи — в базе, в подборке, в чужом листке — кнопка «+» (как
корзина в интернет-магазине). Учитель отбирает задачи, затем в корзине в
шапке решает, куда их сложить: **в новый листок** или **в существующий**.

## Почему это просто сделать

Вся инфраструктура уже есть: листок (`Worksheet`) и его элементы
(`WorksheetItem`), конструктор умеет переставлять и удалять элементы, а
`append_task` (`worksheets/views.py`) добавляет задачу в конец, не создаёт
дубль и **восстанавливает** мягко удалённый элемент. Не хватало только
списка отобранного и кнопок на страницах задач.

Новых моделей нет.

## Механика

1. **Корзина виртуальная** — упорядоченный список id задач в
   `request.session['cart_tasks']`. Листок **не создаётся**, пока учитель
   не нажал одну из кнопок сборки. Первая версия заводила `Worksheet` при
   первом «+» и держала в сессии его id — от этого оставались пустые
   «Новые листки» после случайных кликов; отвергнуто.
2. **Кнопка «+»** — квадрат в размер `.btn-small` с крупным знаком
   (`.cart-btn`), тот же include `includes/cart_button.html`:
   - каталог `/problems/` — отдельная последняя колонка `col-cart`,
     правее тем;
   - страница задачи — в ряду `.form-buttons`;
   - подборка и конструктор листка — в `.ws-actions` строки, слева от
     видимости/стрелок/«×».
   У задачи в корзине кнопка показывает «✓»; повторный клик убирает её из
   корзины. Локальные копии (`Task.variant_of`) в корзину не попадают и
   кнопки не имеют.
   POST на `cart_add` / `cart_remove`: JSON при `X-Requested-With`
   (`ok`, `message`, `in_cart`, `count`), иначе redirect на `next`.
   Уведомление — тост `#ws-saved` через `EgorAutosave.showSaved`.
3. **Индикатор в шапке** — `.btn.btn-secondary` «Корзина» со счётчиком
   (native `<details>`, `includes/cart_menu.html`). В панели:
   - «В новый листок» (`.btn`) → `cart_create`: `Worksheet(title='Новый
     листок')`, задачи в порядке добавления, redirect в конструктор;
   - select личных листков + «В существующий» (`.btn.btn-secondary`) →
     `cart_append`: `append_task` по каждой задаче (без дублей, с
     восстановлением мягко удалённых), redirect в конструктор;
   - «Очистить корзину» (`.linklike`).
   При пустой корзине кнопки сборки `disabled`, «Очистить» скрыта; JS
   (`static/js/cart.js`) держит счётчик и состояние кнопок в актуальном
   виде без перезагрузки. После сборки корзина очищается.
4. **Только личные листки.** `cart_append` берёт цель из
   `owner=request.user, collection__isnull=True` — backing-листки подборок
   и чужие листки дают 404, корзина при этом не теряется.
5. **Один контекст-процессор** `accounts.context_processors.shell` отдаёт
   в шаблоны `is_teacher` (через тот же `get_role`, что и `dashboard`) и
   `cart` (`ids`, `task_ids`, `count`, `choices`). Для учеников и анонимов
   запросов к БД нет.

## Ограничения

- Корзина живёт в сессии: выход из аккаунта или другой браузер — пустая
  корзина. Для «состояния сейчас собираю» этого достаточно.
- Задача, удалённая из базы между «+» и сборкой, просто пропускается.
- Порядок в корзине — порядок добавления; переставлять — уже в
  конструкторе.
