# Проект: полуавтоматическое пополнение базы и нейро-решения

Статус: проект (не реализовано). Пункт 23 плана большой модификации.

## Задачи

1. Пополнять базу из PDF-учебников полуавтоматически (распознавание).
2. Генерировать ответы/решения нейросетями (ChatGPT/Gemini по API) —
   при импорте, при ручном добавлении и для уже существующих задач.
3. Оптимизировать по времени, лёгкости контроля/правок и цене.

## Конвейер распознавания PDF (Mathpix)

Подписка на Mathpix уже есть — используем их **Convert API**
(PDF → Markdown/LaTeX постранично, формулы в `$…$`).

```
PDF учебника
  → Mathpix Convert API (mmd/LaTeX)
  → разрезка на задачи (правила + нумерация)
  → предпросмотр импорта (существующая страница /worksheets/import/)
  → создание задач с дедупликацией (уже реализована)
```

Ключевые решения:

- **Не строить отдельный UI**: результат распознавания приводим к формату
  `\task{…}{…}{…}` пакета egor и подаём в существующий импорт .tex —
  там уже есть предпросмотр, массовое назначение класса/темы/звёзд,
  дедупликация и догрузка картинок.
- Разрезка на задачи — самое хрупкое место. Первая версия: эвристика по
  нумерации («1.», «Задача 3», «№ 4») + ручная правка границ прямо в
  textarea предпросмотра. Если качества не хватит — разрезать LLM-запросом
  (дёшево: только текст, без картинок).
- Картинки: Mathpix отдаёт вырезанные изображения ссылками — скачиваем и
  прикладываем к задачам как `TaskImage` (двухшаговость импорта исчезает
  для этого пути).
- **Загрузчик картинок — с защитой от SSRF и исчерпания ресурсов**
  (обязательные требования к реализации):
  - allowlist хостов: качаем только с доменов Mathpix
    (`cdn.mathpix.com`), только по HTTPS; любой другой URL из ответа
    распознавания — отказ с записью в лог;
  - **автоматические redirect'ы отключены** (`allow_redirects=False`):
    каждый `Location` проходит полный цикл проверок заново — схема
    (только HTTPS), точное совпадение хоста с allowlist, резолв DNS
    с отклонением приватных/loopback/link-local адресов
    (RFC1918/127.0.0.0/8) — и только после этого выполняется следующий
    запрос; лимит числа hop (например, 3), превышение — отказ.
    Redirect с cdn.mathpix.com на любой хост вне allowlist — отказ,
    даже если хост публичный;
  - лимит размера (например, 10 МБ на файл, потоковое чтение с
    обрывом при превышении) и лимит количества файлов на импорт;
  - проверка фактического типа содержимого по сигнатуре файла
    (Pillow/`imghdr`), а не по Content-Type или расширению из URL;
  - таймауты соединения и чтения.

Цена: Mathpix уже оплачен; LLM-разрезка ~0.1–0.5 ¢ на страницу.

## Нейро-генерация ответов и решений

Единая точка: сервис `neuro.solve_task(task) -> {answer, solution}`
(модуль-обёртка над OpenAI/Gemini SDK; провайдер и модель — в настройках).

Промпт: текст задачи + подпункты (LaTeX), системная инструкция «реши,
верни ответ и решение в LaTeX, совместимом с пакетом egor». Формат ответа —
структурированный JSON (`response_format=json_schema` у OpenAI,
`response_mime_type` у Gemini).

Точки вызова (в порядке внедрения):

1. **Кнопка на странице задачи** «Сгенерировать решение» — заполняет
   поля ответа/решения, учитель проверяет и правит (поля уже редактируются
   «горячим способом»). Самый дешёвый контроль качества.
2. **Импорт**: в предпросмотре галочка «сгенерировать решения для
   выбранных» — задачи без ответа получают черновик.
3. **Фоновая очередь** для существующих задач без решений: management
   command `neuro_solve --limit N` (запуск вручную/cron), результат
   помечается флагом `needs_review`, список «на проверку» — фильтр
   в каталоге.

Контроль качества и цены:

- **Черновики хранятся в отдельных полях**, а не в рабочих
  `answer_latex`/`solution_latex`: маркер `answer_source='ai'` сам по
  себе ничего не скрывает — шаблоны и генератор PDF читают рабочие поля
  напрямую, и запись черновика туда немедленно сделала бы его «эталонным»
  ответом во всех существующих путях. Схема: поля
  `draft_answer_latex`/`draft_solution_latex` (+ `draft_created_at`,
  `draft_model`); подтверждение учителем — явное действие «принять»,
  которое копирует черновик в рабочие поля и очищает draft. Существующие
  consumer'ы менять не нужно — они черновиков не видят по построению.
- **Принятие — по отдельным полям, без затирания проверенного**: у задачи
  из фоновой очереди «без решения» может быть корректный, проверенный
  человеком `answer_latex`. Поэтому «принять» — два независимых действия
  (принять ответ / принять решение), а копирование черновика в непустое
  рабочее поле запрещено без отдельного явного подтверждения
  («заменить существующий ответ?»). Генерацию тоже можно сузить:
  для задач с ответом запрашивать у LLM только решение.
- Математика — слабое место LLM: обязательна проверка учителем; ответы на
  вычислительные задачи можно перепроверять вторым дешёвым запросом
  («проверь ответ») или численно (sympy) — этап 2.
- Цена: типовая задача ~1–3 ¢ на GPT-класс моделях; batch API вдвое
  дешевле — подходит для фоновой очереди.

## Порядок внедрения

1. `neuro.solve_task` + кнопка на странице задачи (маленький PR).
2. Mathpix-конвейер: команда `import_pdf file.pdf` → .tex → существующий
   импорт (средний PR).
3. Галочка в предпросмотре импорта + фоновая очередь (маленькие PR).

## Открытые вопросы

- Где хранить ключи API: `.secrets/` (как LATEX_API_KEY) — предлагаю так же.
- Очередь: начать с синхронного вызова и management command; Celery/RQ
  вводить только если появятся реальные объёмы.
