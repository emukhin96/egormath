# Проект: личный кабинет ученика с расписанием занятий

Статус: проект (не реализовано). Пункт 25 плана большой модификации.

## Требования (из постановки)

- В кабинете ученика — не только заданные листки, но и даты занятий.
- Занятия настраивает учитель отдельно для каждого ученика.
- Занятия бывают регулярные (еженедельные) и разовые.
- Учитель может переносить любые занятия — разово или насовсем.
- Домашние задания «привязываются» к занятию.
- Занятия нумеруются.

## Модель данных

Два уровня: правило регулярности и конкретное занятие.

```python
class LessonRule(models.Model):
    """Регулярное занятие: «каждый вторник 16:00 у Пети»."""
    teacher, student
    weekday, time, duration_minutes
    starts_on, ends_on  # период действия (ends_on пусто = бессрочно)
    active

class Lesson(models.Model):
    """Конкретное занятие (и разовое, и материализованное регулярное)."""
    teacher, student
    rule = FK(LessonRule, null=True)   # null = разовое
    number = PositiveIntegerField()    # номер занятия у этого ученика
    scheduled_at, duration_minutes
    status = planned | done | cancelled | moved
    moved_to = FK('self', null=True)   # куда перенесено
    note
```

Ключевое решение — **материализация**: регулярные занятия создаются как
строки `Lesson` заранее (на N недель вперёд, management command +
досоздание при просмотре расписания). Это сильно проще «виртуальных»
повторений: перенос/отмена конкретной даты — обычное редактирование
строки, нумерация — просто счётчик по ученику, привязка домашки — FK.

Перенос:

- **разовый** — у одного `Lesson` меняется `scheduled_at`
  (или `status=moved` + новая строка `moved_to` — если важна история);
- **постоянный** — правка `LessonRule` (старое правило закрывается
  `ends_on`, создаётся новое) + пересоздание будущих незанятых `Lesson`.

Привязка домашки: `Assignment.lesson = FK(Lesson, null=True)` —
одна миграция; на странице назначения листка появляется select
«к какому занятию».

## UI

Учитель:

- на странице ученика (`/students/<id>/`) — блок «Расписание»: правила
  регулярных занятий + ближайшие занятия с действиями «перенести/отменить»
  (native `<dialog>`, как в остальных местах);
- при назначении листка — выбор занятия.

Ученик (dashboard):

- «Ближайшие занятия»: № занятия, дата/время, привязанные листки;
- у листка — подпись «к занятию № 12 (вт 5 марта)».

## Объём работ

1. Модели + миграции + admin (маленький PR).
2. CRUD правил и занятий у учителя + материализация (средний PR).
3. Кабинет ученика + привязка `Assignment.lesson` (маленький PR).

## Открытые вопросы

- Часовые пояса: предлагаю хранить в локальном времени сервера
  (`TIME_ZONE`), пока все в одном поясе.
- Напоминания (email/Telegram) — вне рамок этого проекта, но модель
  их не блокирует.
- Нужна ли оплата/учёт проведённых занятий? Поле `status=done` оставляет
  задел, отчётность — отдельным проектом.
