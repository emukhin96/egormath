# Картинки в задачах

Как пользоваться картинками и как система их хранит и обрабатывает.

## Для пользователя

### Как добавить картинку к задаче

1. Откройте задачу → «Полная форма» (страница редактирования).
2. В блоке «Картинки» выберите файл: **PNG/JPEG** (фото, сканы) или
   **PDF** (векторная графика — схемы из TikZ, чертежи).
3. Сохраните. Картинка появится на странице задачи и будет автоматически
   попадать в PDF листков с этой задачей.

Порядок картинок задаёт поле «Порядок» — оно важно, когда в тексте задачи
есть ссылки на конкретные картинки (см. ниже).

### Ссылки на картинки из текста задачи

Обычно ничего писать не нужно: все картинки задачи выпускаются в PDF
автоматически после условия. Если нужно сослаться на конкретную картинку
в конкретном месте текста (или в подпункте), используйте `\taskpic{N}`,
где `N` — номер картинки по порядку (1, 2, …):

```latex
На рисунке \taskpic{1} изображён график функции.
```

- В PDF `\taskpic` вставляет картинку по механике пакета `egor`:
  ссылки копятся в условии, а сам блок картинок выпускается командой
  `\flushpics` (система добавляет её в конец документа сама).
- Исключение — системы неравенств с вариантами и задания на соответствие
  графиков формулам или знакам коэффициентов: полосы вариантов/графиков печатаются
  непосредственно в условии на ширину строки. Условие и варианты остаются
  одним блоком, чтобы номера и координаты не уменьшались в общей очереди.
- В вебе `\taskpic{…}` из текста вырезается — картинки показываются
  отдельным блоком под условием.
- Картинки, на которые нет ссылок в тексте, добавляются в конец условия
  автоматически.
- Ссылка на несуществующий номер молча убирается — PDF компилируется
  даже до того, как картинки догружены.

### Импорт .tex с картинками (двухшаговый)

Файлы картинок при импорте листка **не переносятся** — переносится только
текст. Порядок действий:

1. Импортируйте .tex как обычно. Команды `\taskpic{файл.pdf}` и
   `\includegraphics{файл.png}` в тексте автоматически заменяются на
   номерные ссылки `\taskpic{1}`, `\taskpic{2}`, …
2. После импорта система покажет предупреждение: каким задачам какие
   файлы нужны (с ссылками на страницы задач).
3. Догрузите файлы на странице каждой задачи — **в том же порядке**,
   в каком они перечислены в предупреждении: номерные ссылки резолвятся
   по порядку картинок задачи.

**Ограничение.** Предупреждение выводится только для задач, *созданных*
этим импортом. Если дедупликация сопоставила задачу с уже существующей
в базе, файлы из исходного .tex игнорируются без предупреждения —
предполагается, что у существующей задачи картинки уже загружены.
Если это не так, проверьте страницу задачи и догрузите файлы вручную.

## Как это устроено внутри

### Хранение

- Модель `problems.TaskImage`: `FileField(upload_to='task_images/')`,
  привязка к задаче, поле `order`. Файлы лежат в `media/task_images/`.
- Допустимые расширения: `png`, `jpg`, `jpeg`, `pdf`
  (`FileExtensionValidator`).
- Растровые файлы при загрузке сжимаются: длинная сторона ограничивается
  `SUBMISSION_PHOTO_MAX_SIDE`, PNG остаётся PNG (прозрачность и схемы),
  остальное конвертируется в JPEG. PDF не трогается.
- `TaskImage.filename` (basename файла в storage) — единое имя картинки
  для `\taskpic` в tex и для передачи в LaTeX API.

### Текст задачи ссылается на картинки по номерам

В базе текст задачи хранит ссылки вида `\taskpic{N}` (номер, не имя
файла). Это развязывает текст и файлы: картинку можно перезалить,
имя файла в storage может измениться — текст остаётся прежним.

- Генерация PDF (`worksheets/latex.py`): `_resolve_taskpics` заменяет
  `\taskpic{N}` на `\taskpic{имя-файла}` по списку картинок задачи;
  неиспользованные картинки дописываются в конец условия; в конец
  документа добавляется `\picsperrow{3}` и `\flushpics`, если есть хоть
  одна картинка. Ограничение ряда сохраняет читаемость чертежей на A5.
- Веб: `\taskpic{…}` вырезается из HTML-версии текста фильтром
  `web_text` (`problems/templatetags/task_extras.py`; после слияния
  PR #10 препроцессор вынесен в `problems/web_tex.py`). Картинки
  рендерятся шаблонами отдельно: растровые — `<img>`; PDF до слияния
  PR #5 показывается ссылкой, после — встраивается через `<object>`
  с fallback-ссылкой (`templates/problems/_task_images.html`).

### Передача в LaTeX API

LaTeX компилируется на удалённом сервере (LuaLaTeX). Файлы картинок
передаются в запросе как `assets`:
`worksheets/services.collect_assets(worksheet)` собирает по всем задачам
листка `{'filename': …, 'content_base64': …}` без дубликатов. Лимит API —
20 файлов; пакеты и шрифты на проде лежат на сервере
(`deploy/vps/latex-files.sh`) и места не занимают, при разработке
(`LATEX_SEND_STY`) `.sty` уходят вместе с картинками.
`\includegraphics` в LuaLaTeX понимает и растровые файлы, и векторный PDF.

### Импорт

`worksheets/import_tex.py`:

- `_extract_graphics` при парсинге заменяет `\includegraphics[…]{файл}` и
  `\taskpic[…]{файл}` на `\taskpic{K}`, накапливая имена файлов
  (повторная ссылка на тот же файл получает тот же номер).
- `create_worksheet` возвращает `missing_images` — список
  `{'task': Task, 'files': […]}`; view показывает предупреждения
  со ссылками на страницы задач для догрузки.
