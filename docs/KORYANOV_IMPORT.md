# Подготовка Корянова: многогранники (ЕГЭ, задача С2)

Профиль `koryanov` — А. А. Прокофьев, А. Г. Корянов. «Математика. ЕГЭ 2013.
Многогранники: типы задач и методы их решения (типовые задания С2)»
(04.12.2012, alexlarin.net; в колонтитуле — «Корянов А.Г., Прокофьев А.А.»,
отсюда имя профиля). OCR — Mathpix, `Корянов ЕГЭ стереометрия.tex`,
SHA-256 `ea520a28f5a098cde1cd9ba26cfd9b78841791aaba68ad83e16fd38462ed9f70`
(6327 строк, рисунки — папка `images` рядом, 165 файлов); PDF —
`Корянов ЕГЭ стереометрия C2.pdf`, SHA-256
`c4f4c599e4828941d08e89dd4c0ee983a57ee87800022a0cfe62270e60b5be2d`
(102 страницы, вёрстка в две колонки, текстовый слой с битыми формулами;
страница PDF = номер страницы книги).

## Разбор

```bash
./venv/bin/python tools/textbook_parser.py --profile koryanov \
  --tasks '/путь/к/Корянов ЕГЭ стереометрия.tex' --output tmp/koryanov-parse
./venv/bin/python tools/koryanov_images.py \
  --tex '/путь/к/Корянов ЕГЭ стереометрия.tex' \
  --pdf '/путь/к/Корянов ЕГЭ стереометрия C2.pdf' \
  --bundle tmp/koryanov-parse/import.json --output tmp/koryanov-parse \
  --zip tmp/koryanov-parse/koryanov-images.zip
```

`koryanov_images.py` кладёт в ZIP только рисунки, на которые ссылаются задачи
пакета (Mathpix-имена совпадают с TEX), и вырезает из PDF рисунки, потерянные
OCR (`crops` в правках, нужен PyMuPDF). В интерфейсе «Импорт → Новая партия»
профиль называется «Корянов».

## Структура книги

Таблица — `problems/data/koryanov_structure.json` (сверена с оглавлением).

- Глава 1 «Расстояния и углы» — параграфы 1.1–1.7 (у 1.3 OCR потерял номер
  главы: `\section*{3. Расстояние от точки до плоскости}`), глава 2 «Площади и
  объёмы» — 2.1–2.3, глава 3 «Дополнения» — 3.1–3.4 (заголовок главы 3 OCR
  оставил строкой без `\section`). Введение и 3.3 задач не содержат.
- **Разобранные примеры** — 120, сквозная нумерация по книге: «Пример N. …»,
  «Решение. …», «Ответ: …». Ключ — «П17»; разбор — авторское решение, ответ —
  после последнего «Ответ:» цепочки. Разбор продолжают «Замечание» и следующий
  способ («2-й способ (метод объёмов)…», «Решение. 2-й способ…»): промежуточный
  ответ первого способа остаётся в разборе. Текст после ответа, который не
  продолжает разбор, — теория следующего метода, в пример не идёт (список —
  `dropped_tails` в диагностике, 16 примеров, сверены с PDF). У примеров на
  построение (3.1) строки «Ответ:» нет — начало теории после разбора задано
  фразой в `example_stops` таблицы структуры (П109, П113, П117).
- **Тренировочные упражнения** — 176, сквозная нумерация (ключ «17»): в конце
  каждого параграфа главы 1 и одним блоком в конце главы 2 (оглавление:
  «Тренировочные упражнения … 81» после 2.3). Номер — по счётчику `enumerate`
  (`\setcounter`) или строкой «17. …» после списка; текст после
  `\end{enumerate}` до следующего номера — перенос колонки, продолжает пункт.
- Путь подборки — глава → параграф → «Примеры с решениями» / «Тренировочные
  упражнения»; упражнения главы 2 — глава → «Тренировочные упражнения».
  Название главы без «Глава N.» (`1. Расстояния и углы`): иначе заливка
  свернула бы параграфы в рубрики одной подборки главы.
- **3.4 «Опорные задачи»** (21 утверждение с доказательством) и «Опорная задача»
  в начале 3.1 — теория, на которую ссылаются разборы; в импорт не входят (как
  «Рабочие теоремы» Потоскуева).
- **Подзаголовки методов** («Координатный метод», «Метод объёмов», «Применение
  теоремы о трёх косинусах»…) — то `\section*`, то строкой в тексте («Метод
  объёмов\\»); список с кодами фасета `METHOD` (`COORDINATE`, `VECTOR`, `TRIG`,
  `EXTRA_CONSTRUCTION`, где они есть в рубрикаторе) — в таблице структуры, метод
  каждого примера — `diagnostics.methods`. Пакет импорта фасеты не переносит —
  поля для них в черновике нет; заполнение `METHOD` — отдельная задача.
- **Темы**: 1.1–1.7 — `GEO.08.04` «Угол и расстояние в пространстве», 2.1 —
  `GEO.09.05`, 2.2 — `GEO.08.05` (площадь сечения), 2.3 — `GEO.09.06`, 3.1 —
  `GEO.08.05`, 3.2 — `GEO.11.04`; упражнения 151–176 — по содержанию (`topics`).
  Классы — 10–11.
- **Ответы и указания** (с. 100–101) — поток «1. … 2. …». Mathpix превратил
  начало строки «N.» в `\item`, а вместо потерянных номеров вкладывал списки
  со `\setcounter` глубиной до 9. Номер пункта — явный только у первого пункта
  после `\setcounter`, иначе следующий по порядку; номер внутри строки
  принимается, только если он следующий («2,4.», «130 .» поток не режут),
  `\mathbf{5 0 .}` внутри формулы закрывает её. «Указание. …» — в авторское
  решение упражнения, ответ «а) …; б) …» — по пунктам с теми же метками.

## Рисунки

- «Рис. N» со сквозной нумерацией (1–162), подпись — `\caption` у картинки
  Mathpix. Ссылка «(см. рис. N)», «на рисунке N», «рис. 126б» ставит рисунок в
  то поле, где стоит: в условие — если ссылается условие (ученик его видит), в
  разбор — если разбор. Номер рисунка книги в задаче не остаётся: «(см. рис. 1)» →
  `\taskpic`, «на рисунке 2» → «на рисунке \taskpic», буква части — «(рис. б)»;
  повторная ссылка исчезает, «как показано на рисунке 23» → «на рисунке».
- Части «рис. 26а … 26г», «126а … 126г» — полосы Mathpix (одна картинка на
  несколько частей); «Рис. 126» подписан дважды (вторая полоса — части в, г),
  «Рис. \(127_{\text{в}}\)» — отдельная картинка части в.
- Рисунок без ссылки внутри разбора ставится в конец разбора с предупреждением
  (`figures_positional`); позиция рисунка — по метке, которая живёт в тексте до
  конца правок OCR. В текущем TEX таких нет: потерянная ссылка П28 («1-й способ …
  (см. рис. 30)», OCR дал разрядку) восстановлена правкой.
- Ссылка с буквой части на рисунок из двух полос («рис. 126а» / «126в») ставит
  только свою полосу: части а, б — первая, в, г — вторая.
- Рис. 109 (пример 96) Mathpix не вырезал — вырезка из PDF `koryanov-p074-1`.
- Примеры на построение П109–П113: условие ссылается на «рис. Nа», а на
  панели «б» того же рисунка уже готово построение или сечение. Панель «а»
  вырезана из PDF (`koryanov-p083-125a` … `koryanov-p085-129a`, `crops` и
  `figures` с ключом «125а» в правках): ссылка «рис. 125а» ставит вырезку,
  «рис. 125б» — рисунок книги целиком. Рис. 130 (П114) — одна панель с
  построенным сечением: он перенесён правкой из условия в разбор, точки в
  условии заданы словами.
- Рисунки теории без задачи (`figures_unreferenced`): 7, 18, 20, 25, 34, 56,
  58, 63, 70, 77, 107, 108, 110, 119–121, 124, 137–148 — в ZIP не кладутся.

## Нормализация OCR

- «Peшeние», «Peueние», «Peueнue» → «Решение.»; «Ombem», «OTBET» → «Ответ».
- «Ответ» внутри выносной формулы (`\text { Ombem: }`, `\text { Ответ }:` в
  `aligned`/`array`) — формула до ответа и строка «Ответ: \(…\).»; «Ответ:» и
  выносная формула строкой ниже — ответ строкой.
- «\(B\) единичном кубе» → «В единичном кубе»; обозначения многогранников и
  точек вне формулы и с кириллическими двойниками («MABCD», «МС», «ВF»,
  «середину Е ребра») — формулой латиницей; латиница внутри русского слова
  («ребpa», «coomветственно») — кириллицей; «равно а.» — \(a\).
- «6 с м», «c м^{3}», `\mathrm{~cm}` → «см» (в выносной формуле — `\text{ см}`);
  `\mathrm{~V}` → V; `\mathrm{och}` → `\text{осн}`; «\(6 см, 10 см\)» → «\(6\) см,
  \(10\) см».
- «30°» в тексте → \(30^{\circ}\); «\(2 \sqrt{30} . C D\)» (конец фразы в
  формуле) → «\(2 \sqrt{30}\). \(C D\)»; «(см. рис. \(31 a\) )» → «(см. рис. 31а)»;
  «$1$-й способ» → «1-й способ»; год в «(МИОО, 2010)» — текстом.
- Перечень равенств одной строчной формулой «\(AC=BD=14, \quad BC=AD=13\)»,
  «\(A B=3, S A=7\)», «\(60^{\circ}, N K=18\)» — по формуле на равенство: в
  листке A5 такая строка уходила за поле. Делится только по запятой вне
  скобок; части без «=» — лишь в начале перечня (имя многогранника, угол),
  точки «\(E, F, P\)» и координаты не трогаются.
- Остатки вёрстки колонок: пробел внутри скобки вокруг формулы «( \(E\) …)»,
  «\(S\) )»; строка из одного `\\` перед абзацем и «Замечание.\\»; `\\` в
  конце фразы; номер шага формулой «$1$. Достраиваем» → «1. Достраиваем».
- Выносная цепочка, перенесённая в книге («…= \\ & =…»), склеивается в одну
  строку, только если она не шире ~32 знаков (`formula_width` в
  `volchkevich_parser`: дробь — по большему этажу, индексы — вполовину; знак ≈
  8pt, строка листка A5 — 336pt). Иначе перенос книги остаётся: склейка
  длинных цепочек П9, П10, П30, П56, П75, П77 уходила за поле на 100–200pt.
- Дальше — общий канон `canon_field` (Волчкевич, `TEXTBOOK_PARSE_QA.md` § 5).
