# Импорт банка ЕГЭ

Документ описывает воспроизводимый локальный импорт банка ЕГЭ
Остромогильского. Это не инструкция загрузки на прод и не создаёт каталог задач.

## Исходные данные

Профиль парсера — `ostromogilsky_ege`. Реестр содержит 1742 карточки. В
импортируемом наборе 1741: пустая PDF-карточка `1.28.1` намеренно исключена.
Структура рубрикатора соответствует проекту ЕГЭ-2027, опубликованному ФИПИ
(версия зафиксирована 12.09.2026; это ещё не окончательная спецификация):
[документы](https://fipi.ru/ege/demoversii-specifikacii-kodifikatory),
[изменения 2027](https://doc.fipi.ru/ege/demoversii-specifikacii-kodifikatory/2027/Plan_izmeneniya_KIM_EGE_2027.pdf).
Книжные разделы 1–20 соответствуют линиям 1–20 этого проекта; раздел 21
и 127 его карточек исключены. Существующие задачи не переразмечаются.

Пути к исходным `.tex` и PDF зависят от локального хранилища. Пример запуска
из корня репозитория (задайте `EGE_TEX` и `EGE_PDF` полными путями):

```bash
./venv/bin/python tools/textbook_parser.py \
  --profile ostromogilsky_ege \
  --tasks "$EGE_TEX" \
  --answers-pdf "$EGE_PDF" \
  --pdf-index var/imports/ege/pdf-index.json \
  --output var/imports/ege
```

`--pdf-index` служит кэшем проверенного индекса PDF: при наличии он повторно
используется, при отсутствии создаётся во время разбора.

## Очереди QA

Очереди PNG для визуальной сверки строятся из подготовленного JSON и индекса:

```bash
./venv/bin/python tools/ege_qa.py var/imports/ege/import.json \
  --output var/imports/ege/qa \
  --index var/imports/ege/pdf-index.json \
  --packets pilot

./venv/bin/python tools/ege_qa.py var/imports/ege/import.json \
  --output var/imports/ege/qa \
  --index var/imports/ege/pdf-index.json \
  --packets review_queue
```

Модели получают только небольшие PNG-вырезки условий и ответов, а не всю
книгу. Каждый пакет привязан к `input_hash`, поэтому повторная проверка может
использовать кэш и не смешивает результаты разных входов.

Проведённые контрольные этапы: 80 пилотных карточек; выборочная приёмка 560
карточек; визуальная сверка 175 сложных ответов основной очереди; 170
автоматических обрезок рисунков, проверенных Terra, и ещё 2 сверенных исключения; контроль 93 из 465
карточек Luna со статусом `ok`.

## Черновики Django

Сначала выполняют проверочный прогон без записи:

```bash
./venv/bin/python public_html/manage.py load_ege_drafts \
  var/imports/ege/import.json
```

После проверки можно создать только черновики указанного пользователя:

```bash
./venv/bin/python public_html/manage.py load_ege_drafts \
  --username USERNAME --commit var/imports/ege/import.json
```

Команда не публикует задачи в каталоге. Идентичный пакет возвращает существующую
партию и сохраняет ручные правки. Другая версия того же исходника требует
явного сопоставления изменений и автоматически не перезаписывает черновики.

Для последующей ручной выгрузки партий черновиков используется:

```bash
./venv/bin/python public_html/manage.py export_textbook_batches \
  --profiles ostromogilsky_ege "$EXPORT_DEST"
```

## Повторная очистка и маски ответов

`clean_ege_drafts --batch ID --report PATH [--pdf SOURCE.pdf] --commit`
очищает только черновики ЕГЭ. Без `--commit` сохраняет журнал проверки.
Журнал содержит состояния до/после; существующий файл не перезаписывается.
Партии с задачами, уже загруженными в каталог, отклоняются. Статусы, темы
и редакторские поля сохраняются. Повторный запуск даёт ноль изменений.

Тот же проход включён в профиль парсера: удаление распознанных элементов
навигации и пустых сеток, оформление обычных чисел через `$…$`. Формулы
и аргументы команд сохраняются. Для 3.10.3 восстановлен рисунок из PDF
(страница 241, координаты и SHA-256 в `ege_cleanup.py`). Ответ 19.26 исправлен
по указанию редактора: перед `{2}` восстановлено объединение; правило
проверяет исходное значение целиком и сохраняет остальные ручные правки.

Маски создаются при загрузке черновиков в каталог из окончательных ответов;
существующая маска учителя не заменяется:

- №1–13: `decimal`; прототипы 9.1/9.3/9.6/9.8 и аналоги: `digits`.
- №14а: `series` для периодических серий, `range` для конечного набора.
- №14б: `number` для одного корня, `range` для нескольких.
- №16/19: `range`; вычисления остальных старших номеров: `number`,
  отношения: `ratio`; вопросы «да/нет»: соответствующий пресет.
- Доказательства и задания «приведите пример» не получают точной маски.
  В этой книге доказательства находятся в №15а/18а; №17 — оптимизация.

`series` принимает объединения арифметических серий рациональных кратных π,
например `πn`, `π/2+πn`, `±π/6+2πn`, с целым параметром n/k/m.
Сравнение точное, по классам остатков; эквивалентные разбиения серий допустимы.
Произвольные функции, неарифметические серии и слишком большие периоды
возвращают «не удалось проверить», а не ошибочное подтверждение ответа.

Локальная повторная проверка партии 22: 1741 задача, изменено 1406, один
восстановленный рисунок. Автоподбор дал 1949 масок для задач/подпунктов;
153 подпункта без авторского ответа и один пример (20.34а) оставлены без маски.
Полная книга моделям повторно не передавалась: очистка и проверка масок
выполняются программно. Точный расход токенов разработки не измерен;
размер текста книги не равен расходу текущей задачи Codex.
